## Phase 3: User Story 1 - Search engines discover every page of the site (Priority: P1) 🎯 MVP

**Goal**: `public/sitemap.xml` is generated automatically at build time, listing every publicly
reachable page across all three locales, each with its cross-language alternates declared.

**Independent Test**: Run the generator directly and confirm its output matches
contracts/sitemap-contract.md's entry count, `<loc>` well-formedness, and per-entry alternates —
independent of User Story 2's `robots.txt` work.

- [X] T001 [P] [US1] Unit test: `generateSitemap(SUPPORTED_CODES, pageKinds, languageSlugs)` returns an XML string whose `<urlset>` root declares both the default sitemap namespace and `xmlns:xhtml`; contains exactly `(pageKinds.length × locales.length) + (languageSlugs.length × locales.length)` `<url>` entries with no duplicate `<loc>` (data-model.md `SitemapUrlEntry` — "No two `SitemapUrlEntry` values may share the same `loc`"); every `<loc>` starts with the site origin `https://helloworld.valdir.dev.br` (data-model.md — "MUST start with the fixed site origin ... ## Dependencies & Execution Order

### Phase Dependencies

- **Setup / Foundational**: None (both phases empty — see notes above).
- **User Stories (Phase 3-4)**: No dependency on each other; both can proceed immediately and in
  parallel.
- **Polish (Phase 5)**: Depends on both stories being complete.

### User Story Dependencies

- **User Story 1 (P1)**: No dependency on User Story 2.
- **User Story 2 (P2)**: No dependency on User Story 1 (it only adds a line to an already-existing,
  already-committed `robots.txt`; it does not need `sitemap.xml` to exist yet to be written or tested
  for content, though the *address it points at* only resolves to real content once US1 ships too).

### Within Each User Story

- T001 MUST be written and fail before T002 is implemented.
- T002 → T003 → T004 are sequential (each depends on the previous file existing).
- T005 has no dependency on T002-T004 and can run any time within US1.
- T006 MUST be written and fail before T007 is implemented.

### Parallel Opportunities

- User Story 1 and User Story 2 can be implemented fully in parallel by different people (different
  target files: `src/build/`, `scripts/`, `package.json`, `.gitignore` vs. `public/robots.txt`),
  coordinating only on `tests/e2e/static-files.spec.js` if both stories' tests land at the same time
  (T006 is the only US2 edit to that shared file; US1 does not touch it).
- T005 in User Story 1 can run in parallel with T002-T004.
- T008 in Polish can run in parallel with the rest of Phase 5's prep; T009 and T010 are sequential
  (automated checks before manual walkthrough) and depend on both stories being complete.
- T011 is gated on external state (deployment) and does not block closing out the rest of the
  feature.

## Implementation Strategy

### MVP First (User Story 1 Only)

1. Complete Phase 3: User Story 1 (`sitemap.xml` generation).
2. **STOP and VALIDATE**: `npm run build && ls dist/sitemap.xml` and confirm its content is valid.
3. Deploy/demo if ready — a sitemap crawlers can find manually (e.g., submitted once in Search
   Console) already delivers value even before `robots.txt` references it automatically.

### Incremental Delivery

1. Add User Story 1 (`sitemap.xml` generation) → validate → demo.
2. Add User Story 2 (`robots.txt` reference) → validate → demo.
3. Polish (lint, full suite, build check, manual quickstart pass).
4. Once deployed, re-run the search-engine audit (T011) to close the loop.

### Parallel Team Strategy

With two people: one does User Story 1 (the generator), the other User Story 2 (the `robots.txt`
line) — fully independent files, no coordination needed beyond both adding their own test block to
`tests/e2e/static-files.spec.js` if timed to land together (only US2 touches that file here).
